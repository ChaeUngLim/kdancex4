# write-commit-message — 한국어 커밋 메시지 (cbea.ms 기반)

근거: Chris Beams, 「How to Write a Git Commit Message」(https://cbea.ms/git-commit/). 일곱 규칙을 한국어에 맞게 옮겼다. 형식과 언어는 사용자 결정(2026-11-19)이다.

## 모양

```
feat(beta): 카드 결제 기한을 15분으로 줄인다
                                                   ← 빈 줄 하나
결제를 시작하고 15분 안에 끝내지 않으면 잡아 둔 자리를 풀어 다른 회원이
신청할 수 있게 했다. 기존 30분은 인기 수업에서 자리만 잡고 결제하지 않는
경우가 많아 대기 회원이 오래 기다렸다.

검증: npm run test:unit 184 passed
```

- **제목**: `<종류>(beta): <메시지>` — 괄호 안은 **늘 `beta`**, 콜론 뒤 한 칸.
- **종류**: `feat`(새 기능) · `fix`(버그) · `docs`(문서·spec·보드) · `refactor`(동작 그대로 구조만) · `test` · `chore`(설정·의존성·규칙) · `perf` · `ci`.
- **메시지는 무조건 한국어.** 코드 식별자·명령·파일 이름·수치처럼 바꾸면 뜻이 달라지는 것만 원문 그대로 둔다(`npm run test:unit`, `FR-295`).

## 일곱 규칙 — 한국어판

| # | cbea 원 규칙 | 한국어로 이렇게 |
|---|---|---|
| 1 | 제목과 본문을 빈 줄로 나눈다 | 그대로. 한 줄로 충분한 커밋은 본문을 쓰지 않는다 |
| 2 | 제목은 50자 안쪽 | 메시지(접두어 뒤)를 **50자 안쪽**으로. 72자(접두어 포함)는 넘기지 않는다 — GitHub 가 자른다 |
| 3 | 제목 첫 글자는 대문자 | 한국어엔 대문자가 없다. 대신 **접두어는 소문자**(`feat`)로 쓰고, 메시지는 핵심 낱말로 바로 시작한다(「~관련」, 「작업:」 같은 머리말 금지) |
| 4 | 제목 끝에 마침표 없음 | 그대로 |
| 5 | 제목은 명령형 | 「**이 커밋을 적용하면 ___**」에 들어맞는 **「~한다」**로 끝낸다. 「~했다」·「~함」·「~수정」·「~추가」 같은 보고·명사형은 쓰지 않는다 |
| 6 | 본문은 72자에서 줄바꿈 | **72칸**에서 나눈다. 한글은 한 글자가 2칸이라 한 줄에 대략 36자다. 손으로 세지 말고 `--fix` 로 나눈다 |
| 7 | 본문은 어떻게가 아니라 무엇을·왜 | 그대로. 어떻게는 코드가 말한다. 본문 내용은 아래 「본문에 담을 것」 |

제목 예:

| 쓰지 않는다 | 쓴다 |
|---|---|
| `feat(beta): 결제 기한 수정` | `feat(beta): 카드 결제 기한을 15분으로 줄인다` |
| `fix(beta): 버그 수정했음.` | `fix(beta): 환불 계좌 이름 비교에서 공백을 무시한다` |
| `docs(beta): Update spec` | `docs(beta): 사업자 상태 점검 규칙을 명세에 넣는다` |
| `docs(penpot): 보드 반영` | `docs(beta): 정산 보드 P1~P6 을 그리고 spec 에 잇는다` |

## 본문에 담을 것 (kdance 는 `core-rules.md`「Git 커밋 / PR 설명」과 같다)

독자는 둘이다 — 개발 6개월차 비전공자와 면접담당자. 있었던 일을 다 적지 말고 가장 중요한 판단 1~2가지로 줄인다. 항목마다 1~3문장.

1. **무엇을, 왜** — 전문 용어는 처음 나올 때 괄호로 푼다. "왜 이 방법을 골랐나" 한 가지를 꼭 넣는다.
2. **SCH·식별자** (있으면) — 번호만 쓰지 않는다: `SCH-04(어댑터 3종: PG/알림/슬롯락)`, `FR-295(수단별 환불 실행)`.
3. **검증** — 돌린 명령과 결과 한 줄(`npm test 192 passed`). 증거 폴더가 있으면 경로를 붙인다(`_workspace/evidence/<작업ID>/`, leave-verifiable-evidence 스킬). 안 된 것·미확인은 과장 없이 한 줄.
4. **가이드 링크** (있으면) — `_workspace/guides/SCH-XX(기능명).html`.

## 커밋 전에 — 순서

1. 메시지를 파일로 쓴다 — scratchpad 에 `msg.txt`.
2. 본문이 3문장 이상이면 윤문한다(kdance 는 `core-rules.md`「AI 티 제거」의 점수 분기 — shim `risk_score` 0 이면 지목된 패턴만 직접 고친다). 제목은 윤문하지 않는다.
3. 줄바꿈과 검사(프로젝트 사본이 없으면 전역 사본):
   ```bash
   W=.claude/skills/write-commit-message/scripts; [ -d "$W" ] || W=~/.claude/skills/write-commit-message/scripts
   python3 $W/lint_commit_msg.py --fix <msg.txt>
   ```
   `# lint_commit_msg  결과: PASS` 가 나와야 다음으로 간다.
4. `git commit -F <msg.txt>` — 메시지를 `-m` 여러 개로 나눠 넣지 않는다(빈 줄·줄바꿈이 흐트러진다).
5. 커밋 뒤 확인: `git log -1 --format=%B | python3 $W/lint_commit_msg.py -`

## 지키는 것

- **커밋은 사용자가 요청할 때만** 한다. 이 스킬은 "어떻게 쓰나" 만 정한다.
- (kdance) 업무 단위로 커밋하고, 그 안에서는 문서 성격별(요구사항·설계·보드·규칙·코드)로만 나눈다. 같은 파일을 주제별로 쪼개지 않는다(`core-rules.md`).
- (kdance) 브랜치는 `main` 에 바로, 푸시는 요청할 때만.
- 끝에 붙는 서명 줄(`Co-Authored-By` 등)은 하네스 설정을 따른다. 그 줄은 영어여도 된다.
