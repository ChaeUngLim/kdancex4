## 1. 슬라이스 범위와 절단 근거

### 1-1. 절단 기준

| 기준 | 이번 회차에 적용한 방식 |
|---|---|
| ① 기존 코드와 이어지는가 | 결제 확정 → 예약 `confirmed` 까지 만들어야 이미 있는 취소·환불(SCH-05(취소 오케스트레이션)) 이 붙을 대상이 생긴다 |
| ② 그것만으로 사용자에게 값이 가는가 | spec 의 독립 검증 「수업 1건 + 사용자 1명으로 가입 → 취향 → 검색 → 결제 → 확정 → 캘린더」 를 그대로 1회차 완료선으로 쓴다 |
| ③ 선행 조건이 충족됐는가 | 외부 키(소셜·본인확인·PG)가 없는 자리는 **가짜 어댑터 + 시드 데이터**로 메운다. 외부를 기다리는 일은 넣지 않는다 |

### 1-2. 회차 구분 — 결론

**1회차(US1-A, 이번 Phase 3·4 대상): 「한 건이 끝까지 돈다」**
수용 시나리오 1·2·3·7 과 6 의 절반(성별 자리 기본 선택·바꾸기)을 넣는다.

**2회차(US1-B, 다음 회차)**: 시나리오 4(일정 겹침 경고)·5(대기 신청)·6 의 나머지 절반(마감 자리 대기)

### 1-3. 수용 시나리오별 판단

| 시나리오 | 내용 | 회차 | 근거 |
|---|---|---|---|
| 1 | 취향 입력 → 조건에 맞는 수업 + 정원 대비 신청 인원 | **1회차** | 독립 검증의 「검색 결과에 그 수업이 나옴」 단계. 단순 필터로 성립한다. 단 Q1(홈 목록: 거르기 vs 정렬) 확인 필요 |
| 2 | 결제 완료 → `confirmed` · 8/12→9/12 · 캘린더 등록 | **1회차** | 슬라이스의 심장. FR-289(확정 후 일괄 처리)의 원자성이 핵심 |
| 3 | 가상계좌 입금 기한 경과 → 자동 취소 · 자리 복구 | **1회차** | 가상계좌는 정규 수업에서도 고를 수 있는 수단이고 이벤트형에서는 계좌이체와 함께 둘뿐인 수단이라(FR-111(상품별 기본 결제수단), 2026-11-10 변경 — 이전: 단건 기본 수단이었으나 정규 수업의 기본은 이제 카드) 기한 처리 없이 열면 자리가 영영 잠긴다. 2회차로 미루면 FR-096(결제 대기 자리 잠금)이 반쪽이 된다 |

| 5 | 정원이 찬 수업 → 대기 순번(멤버십·가입 3개월 체험자) / 비멤버십은 멤버십 안내 | 2회차 | FR-093(대기 신청·순번)이 FR-112c(멤버십 전용 혜택)·FR-112d(신규 가입 3개월 체험)에 묶여 있고, 대기 뒤 흐름(FR-094(대기 1번 결제 기회)·FR-094a(대기 순번 한 명씩 넘김)·FR-095(대기 무응답 승계))까지 와야 값이 생긴다. SCH-28(예약·정원·대기) 카드도 "S0 에서는 기본 대기만" 이라 범위를 따로 잡아야 한다 |
| 6 | 남·여 정원 중 여 자리만 마감 → 여 자리 기본 선택 + 「여 자리 마감 · 대기 가능」, 남 자리로 바꾸면 신청 가능 | **1회차(대기 부분 제외)** | 성별 정원(FR-092(성별 정원))은 정원 데이터 모델 자체다. 나중에 쪼개면 스키마를 다시 고쳐야 한다. 「대기 가능」 문구와 대기 버튼은 2회차. 1회차에서는 마감 자리를 「마감」으로만 표시하고 결제 버튼을 끈다(FR-091a(정원 마감 시 결제·쿠폰 차단)) |
| 7 | 본인확인 성별이 남성 → 남 자리 미리 선택, 여 자리로 바꾸기 가능 | **1회차** | 6 과 같은 모델. 성별 출처는 가짜 본인확인 어댑터(Q2(가입·로그인 방식)) |

## 2. 요구사항 요약 — 무엇을, 왜

| 무엇 | 왜 |
|---|---|
| 회원 1명이 가입하며 성별·생년·연락처를 남기고, 관심 장르·지역·시간대를 입력한다 | 검색 조건과 성별 자리 기본값의 출처다 |
| 홈에서 조건에 맞는 수업과 「정원 대비 신청 인원」·「잔여 남 ○석·여 ○석」을 본다 | 결제 전에 들어갈 수 있는지 판단하게 한다 |
| 자리(남/여)를 고르고 카드(정규 수업 기본, 2026-11-10 변경 — 이전: 가상계좌가 기본) 또는 가상계좌로 결제를 시작하면 그 자리가 `held` 로 잡힌다 | 입금 대기 중에 같은 자리가 이중으로 팔리지 않게 한다(FR-096) |
| PG 통지(웹훅)가 서명·금액 대조를 통과할 때만 예약이 확정되고, 신청 인원·캘린더·알림이 한 번에 반영된다 | 앱 화면의 "완료" 만으로 확정하면 돈 없이 자리가 나간다(FR-287). 일부만 반영되면 정합성이 깨진다(FR-289) |
| 가상계좌 기한(발급 뒤 24시간과 수업 시작 1시간 전 중 이른 쪽, 카드 15분)이 지나면 주문이 만료되고 자리가 풀린다 | spec 「전제 18(결제 기한 기본값)」. 값은 설정으로 둔다 |
| 확정된 예약은 기존 취소·환불 흐름이 붙을 수 있는 모양이어야 한다 | US1 「Why」 — 이미 만든 취소·환불 코드가 붙을 대상 |

## 3. 대상 범위

| 영역 | 이번 회차 | 비고 |
|---|---|---|
| `admin-web/`(Next.js) | **주 작업 영역** — Prisma 8 스키마·마이그레이션, Route Handler(가입·프로필·검색·주문·웹훅·캘린더), 가짜 PG·본인확인 어댑터, 시드 스크립트 | DB 쓰기는 여기 하나(ADR-004) |

## 4. 제약 조건

### 4-1. 버전 정책

- 값은 여기 적지 않는다. 원본은 `docs/planning/kdancex4_service_definition_and_tech_stack.md` 「11. 기술 스택 고정표」, 설치 실제값은 `admin-web/package.json`·`mobile/package.json`
- 확인한 사실만 적는다: Prisma 8 은 RC 단계이고 런타임 패키지 이름이 `@prisma/orm-postgres` 다(`@prisma/client` 아님). `better-auth` 는 `package.json` 의 `overrides` 로 prisma peer 를 덮어쓴 상태다. Expo 58 은 preview, React Native 0.88 은 RC 다
- 새 패키지(테스트 러너 등)를 들일 때는 core-rules 「올리기 전에」 5단계를 따른다. `--legacy-peer-deps` 금지
- 에이전트용 문서 `docs/agent/ai-coding-agent.html` 을 Phase 3 착수 전에 읽는다(구버전 API 로 되돌리는 실수 방지)

### 4-2. 검증선

| 영역 | 명령(각 디렉터리에서) | 기대 결과 | 이번 회차의 역할 |
|---|---|---|---|
| backend 전체 | `uv run pytest -q` | **186 passed**(DB 기동) / DB 미기동 시 159 passed, 27 skipped | 회귀 확인. 손대지 않으므로 숫자가 바뀌면 안 된다. 같은 DB 에 Prisma 마이그레이션을 얹은 뒤에도 186 이어야 한다 |
| backend DB 테스트 | `uv run pytest -m requires_db -q` | 27 passed | 위와 같다 |
| admin-web | `npm run build` | 성공(타입 검사 포함) | 주 검증선 |
| admin-web 테스트 | **러너 없음 — Phase 3 에서 정한다** | — | 수용 기준 테스트는 이 러너로 돈다. 정하기 전까지 아래 명령은 `<runner>` 로 적는다 |
| Prisma | `npx prisma migrate deploy`(또는 Prisma 8 의 해당 명령 — 이름은 미확인, Phase 2·3 에서 설치본 문서로 확인) | `kdance_test` 에 오류 없이 적용 | R2 와 함께 실측한다 |

- **쓰지 않는 검증선**: admin-web `npm run lint` — `eslint.config.mjs` 의 `FlatCompat` 순환 참조로 고장. 결과를 판정에 쓰지 않는다
- 품질 게이트 훅은 0개다(SCH-23(품질 게이트 훅) 대기). 검증은 Phase 6(테스트)이 명령을 직접 돌려야 일어난다

### 4-3. 그 밖의 제약

- 외부 API 는 무료 구간만. 이번 회차는 외부 호출이 없다(가짜 어댑터)
- 모든 금액은 원 단위 정수(FR-283)
- 시각은 KST 기준으로 판정한다(가상계좌 「수업 시작 1시간 전」) — R8(기한 계산 시간대)
- 표기: Owner 는 화면·문서에서 「대표」, 장르 「쌈바」

- Q5(정산 보류 적립 포함 여부): **원장 최소형을 1회차에 넣고 hold 1줄을 적립한다.** 나중에 끼우면 이미 확정된 주문의 원장이 비기 때문이다.
- Q6(첫 수업 데이터 출처): **시드 스크립트.** Q2·Q4 의 시드 선택과 일관된다.
- Q7(PG 결정 상태)~Q12(알림 기록 형태)는 Phase 2(기존 코드 구조 확인)·Phase 3(구현 계획)에서 닫는다.
