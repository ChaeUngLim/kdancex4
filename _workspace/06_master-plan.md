## 1. 이 문서가 정하는 것과 정하지 않는 것

| 정한다 | 정하지 않는다 |
|---|---|

| 가로지르는 설계의 경계(데이터 묶음 소유, 상태 기계, 권한, 어댑터, 시간 작업) | 새 SCH 번호. 슬라이스는 기존 SCH-21(FastAPI→Next.js 전환)~SCH-49(부하 시험)에 대응만 시키고, 번호를 새로 만들지는 오케스트레이터가 정한다 |
| 코드 밖 출시 준비 일과 그 막힘 관계 | 요구사항 자체. 무엇을 왜 만드는지는 spec 이 원본이다 |

번호 체계는 기존 것을 잇는다. ## 3. 원칙

### 3-1. 순서 — 대표 → 강사 → 회원

| 근거 | 내용 |
|---|---|
| 사용자 결정 | 2026-11-07 「플랜은 대표 → 강사 → 회원, US1 플랜은 마지막에 보정, 구현은 R2 스파이크부터」 |
| 값이 흐르는 방향 | 대표가 쓴 환불·취소 공지(FR-099a(환불·취소 공지 양식))가 강사 수업 등록에 자동으로 들어가고(FR-099b(공지 자동 입력)), 그 판본이 회원 주문에 고정된다(FR-284(주문 시점 값 고정)). 강사 소속·권한(FR-071(소속 강사 관리)·FR-081a(강사 위임 범위))이 없으면 강사가 수업을 열 곳이 없다 |
| 보드 준비 | 대표 웹 W1~W8 과 대표 앱 O-a~c 는 끝났고, 강사는 T3·T1·T4 까지 그렸다(`board_plan.md` §6). 회원 C 계열은 화면 문단만 spec 에 들어갔다 |
| 시드를 걷어 내는 순서 | US1 1회차는 학원·수업을 시드로 넣었다(plan §5 US1-A2). 대표·강사 기능이 먼저 생기면 시드는 테스트 픽스처로만 남고, 회원 슬라이스가 실제 데이터 위에 선다 |

**예외 하나.** 강사 명단·오늘 인원·대표 주문 목록처럼 **회원 결제를 읽는 화면**은 M1·M2 에 두지 않고 M3 끝(S3-5)에 둔다. 결제 경로가 없으면 그 화면은 가짜 데이터로만 「끝난」 것이 되기 때문이다(3-2 의 수직 슬라이스 원칙이 이긴다).

### 3-2. 수직 슬라이스

### 3-4. 무료 API 원칙

- 외부 API 는 영구 무료 구간만 쓴다. **결제 PG 자체는 예외**(`provisional-decisions.md` §1)
- 문자 인증은 쓰지 않는다(FR-303(관리자 2단계 인증) — 패스키 기본, 못 쓰면 인증 앱 OTP · 2026-11-13)
- 예금주 확인·사업자 휴폐업 조회·휴대폰 본인확인은 「무료 구간 안에서 가능한 방법으로 — 방법은 확인 필요」로 둔다(`integration.md` 원칙 4). 무료 수단이 없으면 그 자리는 운영자 수동 확인으로 내려간다(R15)
- 로컬 실행이 되면 로컬이 기본값이다(AI 생성·비전은 `kdance-llm`)

- **범위**: FR-085(학원 등록 형태·증빙) · FR-087(증빙 없으면 엄격 기준) · FR-088(등록 형태 표시) · FR-250(입점 심사·게시 제한) · FR-251(입점 조건 동의) · FR-125b(카드 수수료 입점 동의) · FR-249(약관 동의 기록) · FR-070(학원 정보 등록) · FR-248(사업자 정보 표시) · FR-240(통신판매중개자 고지)의 판매자 정보(O-04) · FR-139(강사 계좌 변경 재확인)의 대표 계좌 쪽 · FR-257(가입 거절 사유) · I-05(예금주 확인) · O-17(사업자 상태 재확인)
- **영역**: 학원·지점·입점 신청·증빙 파일·정산 계좌·동의 기록 테이블 · 관리 웹 입점·설정 화면 · 운영자 심사 최소 화면 · 파일 저장 포트(6-8) `[운영 보강 ⑤]`
- **의존**: S0-3 · **위험**: 상(계좌·사업자 정보) · **임시**: 없음(예금주·사업자 조회 수단은 R15)
- **수용**: ① 필수 동의 5항목 중 하나라도 빠지면 신청이 안 된다 ② 증빙 없는 학원에는 엄격 환불 기준이 붙는다 ③ 승인 전 학원의 수업은 게시되지 않는다 ④ 정산 계좌를 바꾸면 2단계 인증을 다시 묻고 변경 알림이 간다 ⑤ 회원에게 보일 판매자 정보 항목이 한 목록에서 나온다 ⑥ 올린 파일이 허용 형식이 아니거나 장당 10MB(추천값)를 넘으면 거부되고, 증빙 파일은 주소를 알아도 그 대표와 운영자만 열 수 있다 `[운영 보강 ⑤]`
- **열린 점**: 증빙 파일 저장 위치(로컬 디스크·무료 객체 저장소) — SP-10 이 정하고, 그때까지는 로컬 디스크 구현으로 간다 · 운영자 심사 화면을 이 슬라이스에 넣을지 S7-4 로 미룰지 · 예금주 확인을 운영자 수동으로 시작할지

#### S1-2(강사 소속·권한 위임·강의실)
- **생기는 것**: 대표가 초대 링크로 강사를 받고, 메뉴 권한을 켜고 끄고, 강의실 주간표에서 겹침을 막는다
- **범위**: FR-071(소속 강사 관리) · FR-011(대표 승인 쪽) · I-01(거절 사유·초대 링크 추천값 7일·1회용) · FR-081(강사 권한 부여) · FR-081a(강사 위임 범위) · FR-082(강사 소속 해제 처리)의 대표 쪽(I-02) · FR-072(강의실 중복 배정 거부) · FR-083(타 학원 일정 불가 시간 표시) · O-11(위임 끄면 즉시 차단) · O-13(위임 변경 감사)
- **영역**: 소속·초대·위임·강의실 테이블 · 관리 웹 W3a~W3c·W3b2 · 권한별 메뉴(W1c)
- **의존**: S1-1 · **위험**: 상(권한)
- **수용**: ① 쓴 초대 링크를 다시 쓰면 거부된다 ② 위임을 끈 순간 그 강사의 관리 웹 세션 요청이 403 이 된다 ③ 남은 회차가 있는 강사의 해제 버튼은 동작하지 않는다 ④ 다른 학원 일정은 「불가 시간」으로만 보이고 내용은 안 보인다 ⑤ 위임 변경이 감사 기록에 전후 값으로 남는다
- **열린 점**: 해제의 「이후 회차 대체·휴강·폐강」 처리는 수업이 생긴 뒤라 S2-3 에서 완성 — 여기서는 남은 회차 0 인 해제만

#### S1-3(환불·취소 공지 양식·노쇼 기준)
- **생기는 것**: 대표가 정규 과정 공지(등록 형태별 템플릿)와 이벤트형 취소 수수료 표를 판본으로 저장하고, 노쇼 회차 기준 안내를 본다
- **범위**: FR-086(등록 형태별 정규 과정 환불 템플릿) · FR-099(환불 규정 등록·표시) · FR-099a(환불·취소 공지 양식) · FR-099c(이벤트·원데이·파티·공연·대회 취소 규정) · FR-099d(환불 마감일 필수 입력·결제 적용) 의 규칙 부분 · FR-246(규정 없는 학원 게시 차단) · FR-135c(노쇼 정산 기준) · FR-284(주문 시점 값 고정) 판본 · O-16 보존
- **영역**: `refund_notice_versions` 확장(정규·이벤트형·개인 레슨 종류) · 노쇼 기준 · W4a·W4b·W8B
- **의존**: S1-1 · **위험**: 중(법률) · **임시**: Q15(노쇼 기준 하나로 고정 — W8B 는 안내 화면) · Q24(취소 수수료는 참가비 기준, 예매 수수료 별도 환불 불가) · Q22(개인 레슨 전용 양식 — 양식 틀만 여기, 사용은 S2-4)
- **수용**: ① 템플릿보다 덜 돌려주는 값은 저장이 거부된다(더 돌려주는 쪽만) ② 공지를 고치면 새 판본이 생기고 옛 판본은 남는다 ③ 이벤트형 취소 수수료는 낮추기만 되고 환불 마감일이 지난 행사에는 못 바꾼다 ④ 공지가 없는 학원의 수업 게시는 거부된다
- **열린 점**: 학원법 반환 기준의 정확한 값(Q11 ① 법률 검토) — 템플릿 값은 초안으로 넣고 검토 뒤 바꿀 수 있게 판본으로 둔다

#### S1-4(학원 공지·대표 대시보드 뼈대·대표 알림함)
- **생기는 것**: 대표가 소속 강사에게 공지를 보내고, 대시보드에서 승인 대기 같은 숫자를 보고, 앱 알림함에서 운영 알림을 받는다
- **범위**: FR-063a(대표의 소속 강사 공지) · FR-078(학원 공지 직접 작성) · FR-079b(대표 대시보드 지표)의 승인 대기 타일 · FR-080(대표 운영 알림)의 기록 · FR-145(관리자 웹 알림)
- **영역**: 공지·알림 기록 · W5 · O1(대시보드)·O21B(알림함, `운영` 칩)
- **의존**: S1-2 · **위험**: 하
- **수용**: ① 공지는 소속 강사에게만 보이고 회원에게는 안 보인다 ② 해제된 강사는 이후 공지를 받지 않는다 ③ 대시보드 타일 숫자가 DB 집계와 같다
- **열린 점**: 대시보드의 결제·환불 타일은 M3·M4 에서 채운다 · 대표 앱(O 계열)을 mobile 안 역할 분기로 둘지(FR-011a(역할별 화면·강사·대표 입구))

### M2 강사

#### S2-1(강사 가입·소속 신청·프로필)
- **생기는 것**: 강사가 앱에 가입해 활동 장르 하나와 프로필을 정하고, 학원에 소속을 신청하거나 초대 링크로 들어온다
- **범위**: FR-011(강사·대표 계정 승인) · FR-011b(강사 활동 장르 하나) · FR-025(강사 프로필) · I-01(강사 쪽: 거절 알림·재신청) · FR-082(강사 소속 해제 처리) 의 강사 쪽 해제 요청 · FR-053(강사 가능 시간)
- **영역**: 강사·소속 테이블 · 앱 M1B·I12·I9(프로필 줄)
- **의존**: S1-2 · **위험**: 중(개인정보) · **임시**: Q23(본인확인은 정산 계좌 등록 전 — 가입 때는 묻지 않음)
- **수용**: ① 활동 장르는 하나만 저장된다 ② 거절된 신청은 사유와 함께 알림 기록이 남고 다시 신청할 수 있다 ③ 여러 학원에 소속돼도 일정은 한 강사 기준으로 겹침을 검사한다
- **열린 점**: 강사 가입 방식 — spec 변경 이력(소셜 자유 가입)과 FR-011(아이디·비밀번호)이 다르다(`instructor.md` 4절). Phase 1 이 spec 현행 문장을 확인한다

#### S2-2(수업 등록·대표 승인·게시)
- **생기는 것**: 강사가 2단계 화면으로 수업을 만들고, 대표가 승인하면 회원 목록에 나온다. 시드 수업이 실제 수업으로 바뀐다
- **범위**: FR-050(강사 수업 등록) · FR-050a(수업 등록 승인) · FR-051(수업 구분) · FR-052(수업 운영 형태) · FR-052a(회차·기간 신청 단위) · FR-057(반복 일정 생성) · FR-054(강사 일정 충돌 거부) · FR-072(강의실 중복 배정 거부) · FR-090(정원·신청 인원 표시) · FR-092(성별 정원) · FR-092c(성별 구분 없는 단일 정원) · FR-099b(공지 자동 입력) · FR-099d(환불 마감일 필수 입력·결제 적용) · I-04(무료 수업 0원) · FR-076(게시 3종 동시 준비)
- **영역**: `classes`·`class_offerings`·`class_sessions`·`seat_pools`(data-model D2) + 승인 기록 · 앱 I2·I2D·I2E·I2S · 대표 앱 O5·O5P
- **의존**: S2-1 · S1-3 · **위험**: 중(가격·환불 마감일이 결제에 직결)
- **수용**: ① 정규 수업 2단계에는 대표 공지가 읽기 전용으로 들어가고 강사는 못 고친다 ② 이벤트형은 환불 마감일 없이 등록되지 않고 개최일 뒤 날짜는 고를 수 없다 ③ 대표가 반려하면 사유와 함께 강사에게 돌아가고 고쳐 다시 낼 수 있다 ④ 같은 강사·같은 시각 두 수업은 학원이 달라도 거부된다 ⑤ 0원 수업도 같은 승인 흐름을 탄다
- **열린 점**: 포스터 초안(SX-2)과 같은 등록 경로를 쓸지 · 「지난 학기 설정 복사」(X-06)는 넣지 않음

#### S2-3(변경·휴강 예고·대타·강사 공지)
- **생기는 것**: 강사가 시간·장소 변경, 휴강 알림, 대타 요청, 수강생 공지를 한다. 결제한 회원 쪽 처리(환불·옮기기 선택)는 S4-3 이 붙인다
- **범위**: FR-055(휴강·보강 통지) · FR-056(시간·장소 변경 통지) · FR-060(대타 요청) · I-10(요청 → 수락 → 대표 확인 → 공지, 정산은 실제 수업한 강사) · FR-063(강사 수업 공지) · O-05 의 규칙(정원은 확정 인원 밑으로 못 줄임, 가격은 이후 결제부터) · FR-082(강사 소속 해제 처리) 해제의 남은 회차 처리(대체·휴강·폐강)
- **영역**: 대타 요청·변경 기록 · 앱 I6B·I13·I14·I14B·I14C·I28·I28B · 대표 앱 O21B(대타 알림) · 관리 웹 W3b·W3b2(해제 확인 창)
- **의존**: S2-2 · **위험**: 중
- **수용**: ① 같은 시간에 일정이 있는 강사는 대타 후보로 고를 수 없다 ② 먼저 수락한 강사로 정해지고 대표 확인 전에는 요청을 취소할 수 있다 ③ 확정 인원 9명인 수업의 정원을 8로 줄이면 거부된다 ④ 가격을 바꿔도 이미 고정된 주문 금액은 그대로다 ⑤ 소속 해제 확인 창의 「받는 회원 M명」은 회차별 예약 회원의 중복을 뺀 수와 같고, 세 회차를 예약한 회원은 알림을 한 건만 받는다 ⑥ 대표가 배정한 대체 강사에게 배정 알림이 가고 그 강사 캘린더에 회차가 들어간다(2026-11-13)
- **열린 점**: 결제 회원이 없는 상태에서는 ③④를 테스트 픽스처로 검증하고 M3 끝에 실제 주문으로 다시 돈다

#### S2-4(개인 레슨 개설·강사 일정)
- **생기는 것**: 강사가 소속 학원을 골라 개인 레슨 수강권을 열고, 한 화면에서 여러 학원 일정을 본다
- **범위**: FR-052c(학원에서 여는 개인 레슨) · FR-135a(개인 레슨 정산 (개설한 학원에서))의 상품 쪽 · FR-099b(공지 자동 입력) 개인 레슨 양식 · FR-058(강사 일정 대시보드) · FR-054(강사 일정 충돌 거부)
- **영역**: 개인 레슨 상품·수강권 · 앱 I10·I10B·I10C·I1
- **의존**: S2-2 · S1-3 · **위험**: 중 · **임시**: Q22(시작 24시간 전까지 변경·취소, 그 뒤 1회 차감, 유효기간 추천값 3개월) · Q14(수수료 5%, 개설한 학원이 결제를 받음)
- **수용**: ① 개인 레슨은 개설할 때 고른 학원의 판매자로 주문이 잡힌다 ② 시작 24시간 이내 취소 요청은 1회 차감으로 처리된다 ③ 일정 대시보드에 두 학원 수업이 겹침 없이 한 줄로 보인다
- **열린 점**: 개인 레슨 시간 조율 수단(X-06)은 넣지 않음 · 수강권 회차 차감을 주문 1건에 묶을지 회차권 테이블을 따로 둘지

### M3 회원 결제 (US1 보정)

#### S3-1(회원 가입·동의·취향 — 화면 보정 포함)
- **생기는 것**: 회원이 본인확인으로 가입하면서 필수·선택 동의를 따로 하고, 취향과 기준 장르를 고른다

### 6-5. 알림 발송 경계

- 알림 **행**은 사건과 같은 트랜잭션에서 쓴다. 발송은 커밋 뒤 `NotificationSenderPort.deliver(ids)`(D7)
- 종류는 거래(끌 수 없음) · 서비스(대기 자리 등, 끌 수 있음) · 광고성(동의 필요, 밤 금지) 셋으로 나눈다 `[임시 확정에 기댐: Q27]`
- 받는 곳은 앱 알림함(항상) + 푸시(권한·설정이 있을 때). 문자는 쓰지 않는다
- 정규 수업 신청·취소는 강사 휴대폰에 보내지 않고 알림함과 홈 표에만(I-08)
- 실패는 재시도 뒤 `delivery_status` 로 남긴다(FR-144(알림 실패 재시도)). S3-4 까지는 `pending` 으로 남고 S7-1 이 발송을 켠다

### 6-6. 감사 기록

수정·삭제할 수 없는 한 테이블에 수행자·시각·대상·전후 값을 남긴다(US10 시나리오 1). 남기는 사건: 결제 전이(`order_events`) · 환불 입력·실행·거절 · 정산 조정·상계·지급 보류 설정·해제 · 지급 승인·완료 · 수수료율 변경 · 권한 위임 변경 · 입점 심사 · 정산 계좌 변경 · 연락처 전체 열람(SC-025) · 명단 내보내기(O-11) · 현장 인원 수정(O-07) · 관리 웹 로그인 실패(O-13) · 운영자의 시스템 데이터 수정. S0-2 가 테이블을 만들고 각 슬라이스가 자기 사건을 넣는다.

### 6-8. 파일 저장 경계 `[운영 보강 ⑤ · 2026-11-12 확정]`

서비스 코드는 저장 포트(`FileStoragePort` — 이름은 제안)만 부른다. 구현은 로컬 디스크에서 시작하고 SP-10 결과로 바꾼다.

| 종류 | 올리는 사람 | 누가 보나 | 처음 쓰는 슬라이스 |
|---|---|---|---|
| 입점 증빙(사업자등록증 등) | 대표 | 그 대표·운영자만. 공개 주소 없음 | S1-1 |
| 학원 사진 | 대표 | 공개 | S1-1 |
| 강사 프로필 사진 | 강사 | 공개 | S2-1 |
| 수업·행사 포스터 | 강사·대표 | 공개. 포스터 읽기(SX-2)의 입력이기도 하다 | S2-2 · S6-4 · SX-2 |
| 문의·신고 첨부 | 회원·강사 | 당사자와 받는 쪽만 | S7-2 |

- 형식은 이미지(JPEG·PNG·WebP)와 증빙용 PDF 만 받는다. 장당 10MB, 올릴 때 긴 변 2,000px 로 줄여 저장한다(모두 추천값)
- 파일 이름은 서버가 새로 짓는다. 올린 사람이 준 이름·경로는 쓰지 않는다(경로 조작 방지)
- 비공개 파일은 권한 판정을 거친 서버 경로로만 내려 준다
- 용량 예상과 무료 한도는 SP-10 에서 잰다. 베타 규모(학원 1~3곳)는 로컬 디스크로 충분하다고 보지만 **실측 전**이다
- 파일도 백업 대상이다(S8-4)

### 9-4. SP-9·SP-10·SP-11 조사 결과 (2026-11-12, 문서 조사만 — 설치·실행은 하지 않았다)

출처는 각 서비스의 공식 가격·문서 페이지다. 「미확인」은 공식 페이지에서 답을 찾지 못한 것이다.

**SP-9(오류 추적 수단) — 결론: 외부 서비스 없이 서버 로그 + 자체 알림함 경보로 간다(10-3 ④ 그대로)**

| 후보 | 구분 | 확인한 것 | 미확인·걸리는 점 |
|---|---|---|---|
| 서버 로그 + 자체 경보 | 로컬 | 한도·키 없음 | 오류를 묶어 보는 화면이 없다 |
| GlitchTip 자체 설치 | 로컬(오픈소스) | Sentry SDK 호환, 자체 설치판은 건수 제한 없음. 메모리 0.5~2GB(출처가 호스팅 업체 글이라 어림값) | 공식 문서로 요구 사양을 확인하지 못했다. 노트북에 컨테이너가 더 늘어난다 |
| Sentry Developer 요금제 | 영구 무료(「forever」 표기) | 사용자 1명 · 오류 5천 건 · 보관 30일 | 한도가 월 단위인지, 상업적 이용 제한이 있는지 미확인. 오류 내용이 해외 업체로 나가 개인정보 처리 위탁 고지가 필요해진다 |

로그만으로 부족해지면 GlitchTip 을 먼저 본다. Sentry 는 쓰지 않는다.

**SP-10(파일 저장소) — 결론: 베타는 로컬 디스크. 외부 저장소는 서버로 옮길 때 다시 본다**

- 용량 추정: 저장소에 있는 시안 이미지 304장 평균이 298KB 다. 긴 변 2,000px 로 줄인 사진을 장당 0.5MB 로 넉넉히 잡으면 베타(학원 1~3곳, 수백 장)는 1GB 아래, 1만 장이어도 5GB 안팎이다
- 실제 제약은 Windows C: 드라이브다 — 425GB 중 **남은 것 63GB**(86% 사용, 2026-11-12 실측). WSL 가상 디스크와 DB·모델·백업이 모두 여기에 쌓인다. 추천값: C: 남은 용량이 20GB 아래로 내려가면 운영자 경보
- 외부 후보

| 후보 | 구분 | 확인한 것 | 미확인 |
|---|---|---|---|
| Cloudflare R2 | 무료 구간 | 월 10GB · 쓰기류 100만 회 · 읽기류 1,000만 회 · 내보내기 요금 없음(표준 저장만) | 무료 구간이 영구인지 페이지에 없다. 결제 수단 등록을 요구한다는 글이 있으나 공식 확인 못 함 — 요구하면 쓸 수 없다(`core-rules.md` 결제 수단 등록 금지) |
| Backblaze B2 | 무료 구간 | 「처음 10GB 는 항상 무료」, 내려받기는 저장량의 3배까지 무료 | 카드 등록 요구 여부 |

**SP-11(노트북 외부 접속 경로) — 결론: 후보는 Cloudflare Tunnel + 자체 도메인 하나뿐이고, 두 가지가 풀려야 한다**

| 후보 | 확인한 것 | 판정 |
|---|---|---|
| Tailscale Funnel | 무료 Personal 요금제는 「비상업적 이용에만 적합」이라고 적혀 있다 | 제외(결제가 오가는 서비스다) |
| Cloudflare Tunnel | 노트북에서 밖으로 나가는 연결만 쓰므로 공인 IP·포트 개방이 필요 없다. 공개 주소로 내보내려면 **Cloudflare 에 올린 도메인이 있어야 한다.** 무료·Pro·Business 요금제의 공개 주소 트래픽은 영상 스트리밍·과도한 대용량 파일 제공이 금지다(사진·API 응답은 언급 없음) | 후보 |

풀려야 하는 것: ① 도메인 구입은 돈이 든다(8절 「도메인」 행에 이미 있는 일이다 — API 가 아니지만 비용이라 사용자 결정) ② Tunnel 이 무료 요금제에 포함되는지와 가입 때 결제 수단을 요구하는지를 공식 페이지에서 확인하지 못했다(외부 글은 무료·50명까지라고 적는다) — 가입 화면에서 확인해야 한다 ③ WSL·Docker Desktop 위에서 재부팅 뒤 `cloudflared` 가 자동으로 다시 뜨는지는 돌려 보지 않았다. 영상은 이 경로로 내보내지 않는다(레벨 카드 연출은 앱 안 자산으로).
