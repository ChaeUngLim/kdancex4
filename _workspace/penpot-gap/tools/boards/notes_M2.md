### C15A · 내 문의 · 환불 요청 상태 — slot 25 · 마이 · `c15a_1.js` → `c15a_2.js`
- 구성: `새 문의 | 내 문의 4` 세그먼트 → 칩(전체·환불 요청·수업 문의) → 카드 4장. 처리 중(쌈바, 답변 기한 11/11 (수), 철회 링크) · 완료(바차타, 60,000원 카드 승인 취소) · 거절(살사, 근거 공지 2항 「1/2 지난 뒤 반환 없음」) · 답변 대기 중(수업 문의, 1영업일 지나 대표에게 다시 알림) → 「예약 카드에도 같은 값」 안내.
- 근거: FR-098b(환불 요청 경로) 보완 「환불 요청 상태」·「정규 과정 환불 처리 기한」, Q21(문의 응답 기한).
- 추천안: 환불 요청과 일반 문의를 한 목록에 둔다. 일반 문의가 늦어지면 「답변 대기 중」, 환불이 늦어지면 「처리 대기 중」으로 낱말을 나눴다.
- spec 초안: 「**화면**(2026-11-10 보드 C15A — 추천안, 사용자 확인 대기): 문의 화면의 `내 문의`에서 환불 요청과 일반 문의를 카드로 보인다. 카드마다 상태 칩(`접수` · `처리 중` · `완료` · `거절` · 답변이 늦으면 `처리 대기 중`/`답변 대기 중`)과 학원·접수일·답변 기한을 적고, 거절이면 대표가 고른 근거 공지 항목을, 완료면 금액·환불 수단을 한 줄로 보인다. 같은 상태 값을 내 예약 카드에도 쓴다.」

### C15B · 환불 요청 상세 · 처리 중 — slot 26 · 마이 · `c15b_1.js` → `c15b_2.js`
- 구성: 수업 요약 + `처리 중` 칩 → 진행 단계 4개(접수 → 처리 중 → 답변 기한 → 완료·거절) → 내가 낸 요청(사유·바라는 것·돌려받을 곳) → 「환불 금액은 학원 대표가 정해요」(앱이 미리 계산하지 않음) → `요청 철회하기`(보조) · `대표에게 메시지 덧붙이기`(주).
- 근거: FR-098b(환불 요청 경로) · FR-098(대표 처리 환불 방식) · 보완 「환불 요청 상태」(철회).
- 추천안: 철회해도 예약은 남는다. 「메시지 덧붙이기」는 같은 문의 대화에 이어 쓰는 것으로 봤다.
- spec 초안: 「**화면**(2026-11-10 보드 C15B — 추천안, 사용자 확인 대기): 환불 요청을 누르면 진행 단계(접수 시각·처리 시작 시각·답변 기한·결과)를 위에서 아래로 보이고, 회원이 낸 사유와 바라는 처리를 적는다. 정규 과정은 금액을 앱이 계산하지 않고 대표가 정한다는 안내를 둔다. 대표가 처리하기 전에는 `요청 철회하기`로 요청을 닫을 수 있고, 철회해도 예약은 그대로 남는다.」
