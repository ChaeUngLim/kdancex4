Penpot MCP 설정과 사용법

Claude 가 K-DanceX4 화면 보드(Penpot)를 직접 고치게 하려면 무엇을 연결해야 하는지, 작업 전에 매번 무엇을 하는지 적었다. 지금까지 막혔던 문제와 해결법도 날짜별로 모았다. 새 문제가 생기면 「작업 일지」 맨 위에 그날 날짜로 이어 적는다.

1. 전체 구조 — 무엇이 무엇과 연결되나

Penpot 은 웹에서 쓰는 디자인 도구다(Figma 와 비슷하다). 우리 보드는 design.penpot.app 에 있는데, Claude 는 이 파일에 바로 접속할 수 없다. 브라우저에 열어 둔 Penpot 탭을 거쳐야만 손댈 수 있어서, 연결이 두 군데 필요하다.

Claude Code이 터미널
─①─▶
Penpot MCP 서버내 PC · 포트 4400~4403
─②─▶
Penpot MCP 플러그인브라우저의 Penpot 탭 안
───▶
K-DanceX4 보드design.penpot.app
연결무엇과 무엇어떻게 켜나끊기면 보이는 증상
①Claude ↔ 로컬 서버이 터미널에서 /mcp → penpot → Reconnect/mcp 에 ECONNREFUSED ... localhost:4401
②로컬 서버 ↔ 브라우저 플러그인Penpot 탭에서 Ctrl+Alt+P → Penpot MCP 열기 → Connect작업 중 No Penpot plugin instances are currently connected
MCP(Model Context Protocol)는 AI 가 바깥 프로그램을 도구처럼 불러 쓰게 해 주는 약속이다. 여기서는 Claude 가 Penpot 을 조작하는 통로라고 생각하면 된다.

로컬 서버가 쓰는 포트

포트역할
4400플러그인 파일 제공 — http://localhost:4400/manifest.json
4401Claude 가 붙는 MCP 주소 — http://localhost:4401/mcp
4402플러그인이 붙는 WebSocket(웹소켓, 계속 열려 있는 양방향 연결)
4403REPL(명령을 직접 넣어 보는 창) — 평소엔 안 쓴다
Docker 는 필요 없다. 서버는 컨테이너가 아니라 npm 패키지(@penpot/mcp 2.15.4)이고, 화면은 이미 인터넷에 올라가 있는 design.penpot.app 을 쓴다. Docker Desktop 이 꺼져 있어도 잘 돈다.

2. 작업 시작 순서 (매번)

서버는 Claude 세션이 백그라운드로 띄우기 때문에 세션을 닫으면 같이 꺼진다. 새 세션에서는 아래를 처음부터 다시 한다. 보통은 "Penpot 보드 수정할래"라고만 하면 Claude 가 1번을 하고 2·3번을 안내한다.

  1. 서버 켜기 (Claude 가 한다) 
    cd ~/.npm/_npx/f4739471492be2e8/node_modules/@penpot/mcp && pnpm run start
    curl -s -o /dev/null -w "%{http_code}" http://localhost:4401/mcp 를 돌려 000 말고 다른 값(예: 406)이 나오면 켜진 것이다.
  2. Claude 쪽 연결 — 이 터미널에서 /mcp → penpot → Reconnect. Reconnected to penpot. 이 뜨면 된다. 반드시 같은 터미널에서 한다.
  3. 브라우저 쪽 연결
    1. 대시보드(파일 목록)에는 플러그인 메뉴가 없다. 파일을 열어 편집 화면으로 들어간다.
    2. 캔버스를 한 번 클릭하고 Ctrl + Alt + P 를 누른다. 안 되면 왼쪽 위 ☰ → 플러그인 → 플러그인 관리자로 간다.
    3. 처음이면 입력칸에 http://localhost:4400/manifest.json 을 넣고 설치한다. 이미 깔려 있으면 Penpot MCP → 열기.
    4. 작은 창이 뜨면 Connect 를 누르고 Connected 로 바뀌는지 본다.
  4. 고칠 내용 말하기 — 화면 이름(예: M4 · 관심 장르 카드)과 바꿀 내용을 말한다. 캔버스에서 요소를 골라 두고 "선택한 거"라고 해도 된다.
플러그인 창은 작업이 끝날 때까지 닫지 않는다. 창을 닫거나 탭이 잠들면 ②가 끊긴다. 크롬이면 설정 → 성능 → 메모리 절약 → 「항상 활성 상태로 유지할 사이트」에 design.penpot.app 을 넣어 두자. 덜 끊긴다.

내가 보기만 할 때는?

연결할 필요가 없다. Penpot 을 열어 보고, 손으로 고치고, ▶(보기 모드)로 프로토타입을 돌려 보는 건 혼자서도 된다. 연결은 Claude 가 읽거나 고칠 때만 필요하다. 한 번 연결했으면 그동안 여러 수정을 몰아서 맡기는 편이 낫다.

5. 작업 일지 (날짜별)

최신 날짜가 위에 온다. 새 문제가 생기면 그날 날짜 상자를 맨 위에 하나 열고, 위 해결표에도 한 줄 추가한다. 항목은 모두 증상 → 원인 → 해결 순서로 적는다.

해결고친 뒤 다시 확인함 · 알려진 제약도구 한계라 돌아가는 방법만 있음 · 미해결아직 남아 있음

2026-10-03 (토)

K-DanceX4 화면 보드를 Penpot 으로 옮긴 첫날이다. 오후에 화면 19개를 짓고, 저녁에 장르 카드와 로그인 배경을 고쳤다. 밤에는 재방문 흐름(05 섹션)을 만들었다.

해결글자 없는 흰색 막대 (M1·M8·O2·R0)

증상
뒤로가기 버튼, 「1+1 참여 학원」 태그, 장르 배지 등 6곳이 빈 흰색 막대로 보였다.
원인
원본 HTML 보드에서는 바탕이 rgba(255,255,255,.18)(흰색 18% 반투명)였다. Penpot 으로 옮길 때 투명도가 빠져 불투명한 흰색이 됐고, 흰 글씨가 그 위에서 보이지 않았다. 8자리 색이 거부되는 문제와 같은 뿌리다.
해결
흰 바탕 안에 흰 글씨만 있는 보드를 모두 찾아 fillOpacity 를 0.18(O2 는 0.2)로 되돌렸다. 원본 값은 docs/prototype/kdance-screens-2026.html 에서 확인했다.

해결흐름 목록에 「Flow 1~7」이 계속 생김

증상
재방문 흐름을 만들고 나니 흐름 메뉴에 「Flow 1」부터 「Flow 7」까지 이름 없는 흐름이 쌓여 있었다.
원인
동작(interaction)이 걸린 보드를 복제하거나 새 동작을 걸면 Penpot 이 시작점 흐름을 저절로 만든다.
해결
동작을 다 건 뒤 Flow 숫자 이름의 흐름을 지우고 「재방문 · 자동 로그인」 하나만 남겼다. 복제한 보드는 showInViewMode 도 다시 켠다.

알려진 제약더블 클릭 동작이 없음

내용
Penpot 프로토타입이 지원하는 동작은 클릭·마우스 올림·내림·N초 뒤뿐이다. "카드 더블 탭 → 홈"은 첫 클릭에 선택 화면(S), 같은 카드를 한 번 더 클릭하면 홈(H)으로 흉내 냈다. 실제 앱에서는 더블 탭으로 구현한다.

해결재생(▶) 버튼을 눌러도 빈 화면

증상
보기 모드에 "페이지에 보드가 없습니다"만 나오고, 흐름 메뉴엔 「Flow 1」이 떠 있었다.
원인
플러그인으로 만든 보드 22개가 모두 showInViewMode = false 였다. 손으로 만든 보드는 처음부터 켜져 있지만, 플러그인으로 만들면 꺼진 채로 생긴다. 「Flow 1·2」는 3초 전환을 걸 때 Penpot 이 저절로 만든 중복 흐름이었다.
해결
최상위 보드 22개를 모두 켜고 중복 흐름 2개를 지웠다. 남은 흐름은 「장르 카드 회전 · M4」「장르 카드 회전 · M6」이다.

알려진 제약카드 이미지를 3초마다 바꾸기

요청
댄스스포츠 카드는 비엔나왈츠↔쌈바, 살사/바차타 카드는 살사↔바차타로 3초마다 자연스럽게 바뀌게 해 달라.
원인
Penpot 에는 보드 안 이미지 하나만 따로 바꾸는 애니메이션이 없다.
해결
M4·M6 화면을 복제해 쌈바·바차타가 들어간 B장면을 만들었다. 그리고 두 화면에 "3초 뒤 상대 화면으로, 0.8초 디졸브(겹치며 바뀜)"를 서로 걸었다. 보기 모드에서만 움직인다.
a.addInteraction('after-delay',
  { type: 'navigate-to', destination: b,
    animation: { type: 'dissolve', duration: 800, easing: 'ease-in-out' } }, 3000);

해결여백 값을 바꿨는데 화면이 안 바뀜 (M4 하단 여백)

증상
장르 카드를 2:3 세로로 키웠더니 M4 하단 여백이 20px 에서 9px 로 줄었다. 카드 위 여백을 줄여도 위치가 꿈쩍하지 않았다.
원인
layoutChild 여백이나 rowGap 만 바꾸면 flex 가 다시 배치되지 않는다.
해결
자식 하나를 resize(w, h+1) 했다가 되돌리자 다시 계산됐다. 하단 여백 20px 을 확인했다.

해결배경 이미지가 화면 위를 덮어 버림 (M1 로그인)

증상
새 로그인 배경이 M1 안이 아니라 캔버스 위에 1266×844 크기로 떠서 M1·M2 를 가렸다.
원인
이미지를 올린 직후, M1 안으로 옮기라는 명령을 보내기 전에 플러그인 연결이 끊겼다.
해결
다시 연결한 뒤 M1 맨 뒤로 넣었다. 처음엔 화면을 꽉 채우느라 그림이 너무 확대돼 보였다. 그래서 폭에 맞춰 390×260 으로 줄이고, 위아래를 그라데이션으로 배경색(#0B0B1A)에 섞었다(A안).

알려진 제약작업 중 플러그인이 자주 끊김

증상
하루에 네 번 No Penpot plugin instances are currently connected 가 났다.
원인
① 큰 화면을 내보내다 30초를 넘기면 연결도 같이 떨어졌다. ② 코드 안에서 setTimeout 으로 기다려도 시간 초과가 났다. ③ 탭을 오래 뒤에 두면 크롬이 탭을 재운다.
해결
큰 화면은 내보내지 않는다. 확인이 필요하면 HTML 미리보기를 따로 만들거나 캡처를 부탁한다. 바꾸는 명령과 확인하는 명령도 나눠서 보낸다.

해결/mcp 재연결이 ECONNREFUSED

원인
서버를 띄웠던 이전 Claude 세션이 끝나면서 서버도 꺼졌다.
해결
2장 1번 명령으로 다시 켜고 /mcp 를 재연결했다. 그다음 브라우저 플러그인도 다시 연결해야 했다. 연결이 두 군데라는 건 이때 정리했다.

해결이미지 올리기 http error

원인
장르 이미지 이름은 .jpg 인데 내용은 PNG 였다.
해결
file 명령으로 실제 형식을 확인하고 .png 로 복사해 올렸다. 한글 파일 이름도 영문으로 바꿔 복사해 두면 안전하다.

알려진 제약다른 페이지에 그렸는데 원래 페이지에 생김

원인
openPage 는 가리키는 페이지만 바꿀 뿐이고, 실제로 그려지는 곳은 브라우저가 보고 있는 페이지다.
해결
페이지를 나누지 않고 한 페이지(「K-DanceX4 화면 보드」) 안에 섹션으로 나눠 배치한다.

알려진 제약텍스트 크기·레이아웃이 소리 없이 깨짐

내용
자동 크기 텍스트는 높이가 1px 로 남는다. 글자 폭을 계산해 크기를 직접 넣는다. resize() 를 하면 「폭 채우기」가 풀리니 다시 켠다. alignItems = "stretch" 는 줄 높이를 0 으로 접어 버리니 "start" 를 쓴다. 8자리 색(#00000010)은 거부되니 투명도는 따로 준다.
