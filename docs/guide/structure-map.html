1. 다섯 층으로 본 저장소

이 저장소는 코드보다 문서와 규칙이 많다. 폴더 이름이 아니라 역할로 나누면 다섯 층이 된다. 앞의 넷은 core-rules.md 의 4계층(환경·명세·파이프라인·공구)이고, 다섯째는 사람과 에이전트가 읽기만 하는 설명 층이다. 애매하면 「코드를 보는가」로 가른다.

2. 전체 트리 — 폴더와 파일마다 한 줄

폴더를 눌러 펼친다. 검색창에 파일명이나 설명의 일부를 넣으면 맞는 줄만 남는다. 배지는 층(테두리)과 성격(채움)이다.

원본 다른 파일이 참조하는 단일 진실 원천
파생 원본에서 만들어지거나 원본을 요약
로컬 git 이 추적하지 않음
폐기예정 결정은 났지만 파일은 남아 있음
재생성 명령 한 번으로 다시 만들 수 있음
설치본 외부 도구가 깔아 둔 것 — 손으로 고치지 않음
미추적 아직 git add 하지 않은 새 파일

3. 소스 구조 정의 — 코드는 어떤 층으로 쌓이나

backend 의 한 요청은 위에서 아래로 흐른다. 각 층은 바로 아래 층만 부른다(schemas 가 services 를 읽는 한 방향 예외가 하나 있고, 순환은 없다). SCH-21(FastAPI→Next.js 전환) 뒤에도 이 여섯 구분은 그대로 가져간다 — 폴더 이름만 Next.js 식(app/api/ · server actions · lib/ · prisma/)으로 바뀐다.

문요청이 들어오는 곳
main.py · routers/

HTTP 를 받아 모양으로 바꾸고 판단에 넘긴다. 업무 규칙을 쓰지 않는다

모양요청·응답의 형태
schemas/

Pydantic 모델. 검증은 여기서 끝낸다

판단업무 규칙
services/

취소 11단계 같은 순서와 조건. DB 와 바깥 세상은 경계를 통해서만 만진다

경계바깥 세상과의 접점
adapters/ · deps.py

PG · 알림 · 슬롯락의 Protocol + Fake. 인증 · 주입도 여기

데이터저장
models/ · db.py · alembic/

테이블과 세션. 판단을 넣지 않는다

검증테스트
tests/

층마다 짝이 있다 — 판단 50 · 경계 33 · 모양 39 · 전 층 DB 27

admin-web · mobile · infra 는 어떻게 나뉘나

패키지지금어디로 가나
admin-web/app/(라우트·레이아웃) · components/(화면 조각) · lib/(API 호출). 환불 비율표 화면은 ⛔ 폐기 예정SCH-21 부터 제품 API 가 여기로 온다 — app/api/(문) · server actions(판단) · prisma/(데이터) · lib/(경계). DB 를 쓰는 곳은 Next.js 하나(ADR-004)
mobile/App.tsx 데모 하나 — 화면·API 호출이 한 파일SCH-32·33 에서 화면(app/) · 상태 · API 클라이언트로 나눈다. 모델은 부르지 않고 Next.js API 만 부른다
infra/docker-compose.yml 하나에 DB · Redis · llama-server · ollama운영 전환 때 임베딩·리랭커(vLLM)가 추가된다. 포트와 컨테이너 이름은 CLAUDE.md 가 가리킨다
AI 에이전트 서버아직 없음Python(FastAPI + LangGraph) 별도 프로세스. DB 는 MCP 도구로 읽기만(ADR-004)

무엇을 만들 때어디에 · 어떻게
