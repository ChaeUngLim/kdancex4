## 13. 권한 구조

실제 서비스에서는 사용자 역할을 분리한다.

```text
                    User
                     │
           ┌─────────┼─────────┐
           ↓         ↓         ↓
         Dancer    Instructor   Owner
           │         │          │
        사용자 기능  강사 기능   관리자 기능
                              │
                              ↓
                         Admin/Operator
```

#### 권한 예시

| 역할 | 핵심 권한 |
|---|---|
| Dancer | 검색/추천/예약/일정 |
| Instructor | 수업/일정/수강생 관리 |
| Owner | 댄스학원/강사/수업/회원/매출 |
| Admin | 앱·웹 시스템 관리 — 계정·앱 오류·신고·개인정보 삭제·결제 시스템 장애 · **플랫폼 정산 콘솔**(조회, 수수료율 설정) · 입점 심사·정산 보류·이용 제한 조치(FR-250(입점 심사·게시 제한) · FR-252(정산 보류) · FR-254(이용 제한 절차)). 학원 문의·분쟁은 다루지 않는다(2026-09-25 변경) |

## 12. Web / Mobile 역할 분리

### Web

**React + Next.js**

대상:

- 일반 사용자 Web
- 강사 Web
- 대표/관리자 Web
- 운영자/Admin — 앱·웹 시스템 관리와 **플랫폼 정산 콘솔**(아래)

```text
Next.js
      ↓
React
      ↓
Web UI
      ↓
Vercel AI SDK
```

> 버전은 적지 않는다. 값의 원본은 「11. 기술 스택 고정표」 하나다(19절과 같은 원칙).

### Mobile

**React Native** (Expo SDK 가 버전을 고정한다 — 값과 앵커 선택 이유는 「11-1. 버전을 이렇게 정한 이유」)

대상:

- 일반 사용자
- 강사 모바일 관리

주요 기능:

- 수업 검색
- 추천
- 일정
- 알림
- 파티
- 공연
- 지도
- 이미지 업로드
- 오프라인 대응

#### 플랫폼 관리자 정산 콘솔 (spec FR-300~FR-319, 2026-09-25)

대표 관리자 웹과 **같은 로그인 화면·같은 콘솔**을 쓴다. 들어갈 곳을 고르는 화면은 없고, 계정 권한에 따라 사이드 메뉴만 달라진다 — 대표는 학원 관리 메뉴 전체, 대표가 권한을 준 강사는 위임받은 메뉴만, 플랫폼 관리자는 「플랫폼 정산」 메뉴가 더 보인다(2026-11-10 변경, spec FR-300(로그인 하나·콘솔 하나)). 콘솔은 **조회 전용**이고, 바꿀 수 있는 것은 수수료율 설정·공휴일 입력(P9)·예금주 확인과 반려(P10)·사업자 점검 소명 처리(P11) 넷이고 모두 감사 기록을 남긴다(2026-11-20 보드 대조 — 이전: 「수수료율 하나다」). 대표 수수료를 정하는 근거를 보려고 만든다.

| 화면 | 보여주는 것 | spec |
|---|---|---|
| 대시보드 | 결제·환불·순결제액, 이용 수수료(실제·면제가 없었다면), 멤버십 수입·플랫폼 비용(멤버십 결제가 열린 뒤 — 2026-11-20 사용자 결정), 대표 부담 비용, 활동 학원·강사·수강생 수, 전기 대비 증감 | FR-304 · FR-305 |
| ~~장르별 결산~~ | 삭제(2026-11-24 사용자 결정 — 정산은 학원 단위) | FR-306 |
| 학원별 결산 | 정렬되는 목록 → 학원 상세(수업·강사별 매출, 정산 단계, 쿠폰·카드 수수료, 면제 종료일) | FR-307 |
| 상품·결제수단·지역별 결산 | 정규·원데이·개인 레슨 등 / 가상계좌·카드 등 / 시·구 | FR-308 · FR-309 |
| 전체 결산표 | 총 결제액 → 환불 → 대표 부담 → 수수료 → 학원 지급액, 플랫폼 손익(멤버십 결제가 열린 뒤 — 2026-11-20 사용자 결정) | FR-310 |
| 지급 현황 | 학원 정산 예정·완료·보류, 강사 정산 합계, 다음 정산일 | FR-311 |
| 수수료 책정 근거 | 학원별 플랫폼 기여, 대표 부담 비율, 모의 계산, 규모 구간별 분포 | FR-312~FR-315 |
| 수수료율 설정 | 오늘+30일 이후 날짜부터만 적용(2026-11-20 사용자 결정 D17 — 이전: 미래 날짜부터만), 모든 대표에게 개별 사전 통지, 결제 시점 수수료율 고정 | FR-316 |
| 공휴일 관리 (P9) | 공휴일 더하기 (2026-11-20 보드 대조 추가) | FR-301 |
| 예금주 확인 (P10) | 확인·반려 (2026-11-20 보드 대조 추가) | FR-301 |
| 사업자 점검 (P11) | 소명 받아들이고 풀기·게시 중단 (2026-11-20 보드 대조 추가) | FR-301 |

- 수강생 개인정보는 보이지 않는다. 학원·강사·수업 단위 숫자만 보인다(FR-302(콘솔 개인정보 비노출)).
- 대학생 할인 등으로 줄어든 수업료는 **대표 부담**이다. 1+1 추가 수업은 결제가 0원이라 계산에 넣지 않는다(FR-119(쿠폰·할인 차액 대표 부담)). 그래서 수수료를 정할 때 대표가 이미 부담하는 비용을 함께 본다(FR-313(대표 부담 비용)).
- 합계는 매일 원장과 대조하고, 정산이 끝난 달은 잠근다(FR-318(원장 대사) · FR-319(기준 시각·월 마감)).
