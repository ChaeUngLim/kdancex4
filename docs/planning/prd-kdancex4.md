## 1. 한눈에

### 1-1. 제품 한 문장

K-DanceX4 는 소셜 댄스(댄스스포츠·아르헨티나 탱고·스윙댄스·살사/바차타) 학원 수업을 회원이 취향·일정·레벨에 맞춰 찾고 결제하며, 강사는 수업과 수강생을, 대표는 학원·강사·정산을 한곳에서 관리하는 Android 앱과 관리 웹이다.

### 1-2. 누구의 어떤 문제를 푸나

| 누구 | 푸는 문제 |
|---|---|
| 회원(수강생) | 여러 학원·강사의 수업을 한곳에서 찾고, 정원·일정 충돌을 확인한 뒤 바로 결제한다 |
| 강사(프리랜서) | 수업을 올리고 인원·명단·일정을 보며, 수업이 끝난 몫의 정산을 앱에서 확인한다 |
| 대표(학원 운영자) | 수업 승인·환불 처리·강사 관리·정산을 한 콘솔에서 한다. 수기 결제 정리를 줄인다 |
| 운영자(플랫폼) | 앱·웹 시스템만 관리한다. 학원 결제·환불 분쟁은 다루지 않는다 |

### 1-3. 돈이 흐르는 길

1. 회원이 앱에서 결제한다. 모든 유료 결제는 결제대행사(PG) 한 경로로 들어간다(FR-110(PG 단일 결제 경로)). PG 는 포트원을 전제로 설계한다(spec 전제 3).
2. PG 결과 통지(웹훅 — PG 가 서버로 보내는 결과 알림)로만 결제를 확정한다. 확정되면 예약 확정·인원 반영·캘린더 등록·알림·정산 `보류` 적립이 한 번에 일어난다(FR-287(웹훅 확정)·FR-289(확정 후 일괄 처리)).
3. 학원은 PG 의 하위 판매자다. PG 가 판매 수수료 5%·예매 수수료 2,000원·취소 잔여금의 플랫폼 몫 50%를 플랫폼 계좌로, 나머지를 학원 계좌로 나눈다. 플랫폼은 학원 몫을 쥐고 있지 않는다(FR-282d(정산 분배로 학원 직접 지급)).
4. 지급 시점은 상품마다 다르다. 이벤트형은 환불 마감일이 지나면 바로, 정규·단기 과정과 개인 레슨은 수업 기간이 끝난 몫을 매월 5일에 지급한다(FR-282e(이벤트형 환불 마감 뒤 즉시 지급)·FR-125(학원 월 정산)).
5. 강사 몫은 앱이 강사별로 계산하고, **대표가 확인·승인하면 한 번에 지급**한다. 베타에는 대표가 지급 목록을 내려받아 은행 대량이체로 보내고 앱에서 「지급 완료」를 누른다. 정식 운영에는 같은 승인 버튼이 PG 지급대행을 부른다 — **임시 확정**(Q14(돈이 흐르는 길)).
6. 멤버십(회원)과 수업 관리 플러스(강사 구독)는 플랫폼 상품이라 전액 플랫폼 수입이다(FR-112b(멤버십은 플랫폼 상품)·FR-112e(수업 관리 플러스)).
7. 환불은 대표가 실행한다. 정산이 끝난 건을 환불하면 되돌리지 않고 다음 정산에서 상계한다(FR-295(수단별 환불 실행)·FR-132(정산 조정)·FR-253(정산 상계)).

### 1-4. 출시 단계

spec 의 규모 단계(「규모 단계와 통과 조건」)를 그대로 쓴다. 앞 단계의 통과 조건을 채워야 다음 단계로 간다.

| 단계 | 규모 | 이 PRD 의 구분 | 통과 조건(요약) |
|---|---|---|---|
| S0 내부 | 노트북 1대 · 시험자 1명 · AI 동시 10명 | 출시 전 | 결제·수강 완료·정산·취소·환불 각 1건이 정합성 지표 위반 없이 완료, SC-040~SC-048(혼자 3초·8초 ~ 저하 모드 30초) 통과 |
| S1 베타 | 실사용자 1~10명 · 학원 1~3곳 · 동시 접속 100명까지 | **베타** | 포스터 자동 등록 성공, 학원이 스스로 수업 게시, 강사가 첫 정산을 이의 없이 받음, 문의 경로 동작 |
| S2 운영 초기 | ~1,000명 · 학원 10곳 | **정식** | 재결제율(SC-021) 측정, 문의율(SC-022) 2% 미만, 정산 이의율(SC-022b) 1% 미만 |
| S3 운영 목표 | ~10,000명(3년 이후) | 정식 | SC-016·SC-017 부하 시험, SC-018(가용성 99.5%)·SC-023(보안 치명 0건) |
| S4 설계 상한 | ~100,000명 | 설계 기준 | 구조 변경 없이 증설만으로 SC-017a(10만 설계 상한) 통과 |

베타 사용자 수(10명)와 S0 의 AI 동시 사용자 수(10명)가 같아 베타 전체를 노트북 수용량 안에서 운영할 수 있다. 서버 이전은 S2 로 넘어가기 전에 정한다. 배포는 Android 단일, 갤럭시 스토어다(spec 전제 2).

## 2. 문제와 기회

근거는 정의서·spec·`docs/planning/plan-summary.md` 에서 가져왔다. 입점 설명회 자료의 수치는 그 자료가 제시한 값이고, 이 PRD 가 따로 검증하지 않았다.

### 2-1. 학원(대표)

| 지금의 불편 | 근거 | 제품의 답 |
|---|---|---|
| 블로그·SNS 로는 장르 취향이 맞는 잠재 수강생을 걸러 찾기 어렵다. 신규 문의의 67%가 검색에서 온다는 수치를 설명회 자료가 제시했다 | `plan-summary.md` 3절 | 장르·레벨·지역·시간 검색과 1+1 참여 학원 검색 순위(FR-121d(1+1 참여 학원 실시간 수업 검색 순위)) |
| 수업의 1/5 이 노쇼·지각이고 예약 확인·알림을 원장이 손으로 한다(설명회 자료 수치) | 같은 곳 | 결제 즉시 캘린더 등록·수업 전 알림(FR-140(수업 전 알림 시점)) |
| 현금·계좌이체·카드가 섞인 결제 내역을 손으로 정산하는 데 월 6시간을 쓴다(설명회 자료 수치) | 같은 곳 | PG 단일 결제와 정산 원장(FR-110 · FR-125e(취소 수수료 5:5·판매 수수료 5%)) |
| 수업 등록이 번거롭다 | spec US3(포스터 등록) — 「포스터 한 장만 올리면 나머지는 저희가 합니다」가 입점 설득 논리 | 포스터 자동 추출 + 검토 필수(FR-073(포스터 자동 추출)·FR-074(추출 검토 필수)) |

### 2-2. 강사

| 지금의 불편 | 근거 | 제품의 답 |
|---|---|---|
| 여러 학원을 다녀 일정이 흩어진다. 설계 기준에 「강사 한 명이 주 10개 학원」을 넣었다 | spec 변경 이력 2026-10-09 | 학원별 색 캘린더, 다른 학원 시간과 겹치는 수업 저장 거부(FR-054(강사 일정 충돌 거부)) |

### 2-3. 회원

| 지금의 불편 | 근거 | 제품의 답 |
|---|---|---|
| 여러 학원·여러 강사 수업을 동시에 다녀 일정 충돌이 가장 흔한 불만이다 | spec US4(일정 충돌·알림) | 경고 후 진행 선택(FR-035(일정 겹침 표시), Q6 확정) |
| 남·여 짝을 맞추는 수업이라 정원이 성별로 갈린다 | spec FR-092(성별 정원) | 「잔여 남 ○석·여 ○석」 표시와 성별별 마감 |
| 인기 수업은 자리가 없다 | spec US1 시나리오 5 | 대기 순번과 한 명씩 결제 기회(FR-093 · FR-094a(대기 순번 한 명씩 넘김)) |
| 환불 규정이 학원마다 달라 미리 알기 어렵다 | spec FR-098(대표 처리 환불 방식) | 결제 전 학원 환불 공지 표시 필수(FR-282(결제 화면 필수 표시)) |

**기회.** 양면 시장이라 수요(회원)와 공급(강사·대표) 중 한쪽만 있어도 거래가 0건이다. 그래서 US1(수업 찾아 결제)과 US2(강사 수업·자리 관리)를 함께 P1 으로 둔다. AI 추천은 차별점이지만 게시된 수업이 쌓인 뒤에 실사용자에게 켠다.

## 3. 목표와 성공 지표

### 3-1. 사업 목표

| 목표 | 설명 |
|---|---|
| G1 거래가 끝까지 돈다 | 수업 1건이 등록 → 승인 → 결제 → 수강 → 정산까지 사람 손 없이 맞게 흐른다 |
| G2 돈과 자리가 틀리지 않는다 | 정원 초과·금액 불일치·중복 환불이 0건이다 |
| G3 학원이 스스로 쓴다 | 입점 학원이 직접 수업을 게시하고 환불·정산을 처리한다 |
| G4 회원이 다시 온다 | 첫 수업 뒤 두 번째 결제로 이어진다 |

## 4. 사용자와 역할

역할은 넷이다. 한 사람이 여러 역할을 함께 가질 수 있다(FR-004(역할 4종·복수 역할)).

## 6. 핵심 흐름

### 6-1. 수업 찾기 → 결제 → 확정

1. 회원이 가입한다 — 소셜 로그인, 휴대폰 본인확인, 나이·성별·연락처 필수(FR-002(가입 정보 수집·고지)). 필수 동의(이용약관·개인정보·학원 제3자 제공·만 19세 이상 — 2026-11-11 변경, 이전: 만 14세 이상. FR-249(약관 동의 기록)·Q17(미성년자 결제 동의) 임시 확정에 맞춤)와 선택 동의(광고성 알림·위치)를 나눈다 — 추천안.
2. 관심 장르·세부 장르·지역·시간을 고른다. 1회차 홈 목록은 입력한 지역·시간대로 거른다(FR-022(사용자 프로필)).
3. 수업 상세에서 정원(「잔여 남 ○석·여 ○석」), 학원 환불·취소 공지, 등록 형태를 본다(FR-092 · FR-099(환불 규정 등록·표시)).
4. 결제를 누르면 일정 겹침을 검사한다. 겹치면 막지 않고 겹치는 수업을 보여 주며 진행 여부를 묻는다(M8W).
5. 결제 화면에 가격 내역·환불 공지·통신판매중개 고지가 모두 있어야 결제 버튼이 동작한다(FR-282).
6. 결제를 시작하면 자리를 `held(대기)` 로 잡는다(FR-096(결제 대기 자리 잠금)).
7. PG 통지를 서명·금액 대조로 검증하고 확정한다. 예약 `confirmed`, 인원 증가, 캘린더 등록, 회원·대표 앱 알림, 정산 `보류` 적립이 한 번에 처리된다(FR-289).

### 6-2. 취소·환불

**정규 과정 · 단기 과정 · 개인 레슨**

1. 회원이 앱 문의에서 자기 예약을 골라 환불을 요청한다. 계좌 결제분이면 환불 계좌를 입력한다(FR-098b · FR-295).
2. 담당 강사가 알림을 받고 내용을 확인한다. 결정하지 않는다.
3. 대표가 환불 여부, 금액(0원 ~ 결제액), 근거 공지 항목을 입력한다. 중도 환불이면 진행·남은 회차와 회차당 금액을 계산 보조로 본다(FR-293(대표 환불 입력)·FR-294(중도 환불 계산 보조)).
4. 대표가 관리 화면에서 PG 환불을 실행한다. 카드는 승인 취소·부분 취소, 계좌 결제는 환불 계좌로 송금한다.
5. 회원에게 금액·수단·예상 반영 시점·근거를 알린다 — 추천안.

**이벤트 · 원데이 · 파티 · 공연 · 대회(이벤트형)**

1. 회원이 예약 상세에서 취소를 신청한다. 문의를 거치지 않는다.
2. 시스템이 취소 수수료 표와 주문 시점 값으로 환불액을 미리 채운다(FR-099c(이벤트·원데이·파티·공연·대회 취소 규정)).
3. 대표는 확인하고 실행한다. 금액은 올리기만 할 수 있고 거절할 수 없다.
4. 처리 기간(상한 3영업일) 안에 실행하지 않으면 시스템이 계산된 금액으로 PG 환불을 자동 실행한다(FR-295).

### 6-3. 대기

1. 정원이 차면 결제 버튼과 쿠폰이 꺼지고 대기 신청만 보인다(FR-091a).
2. 대기 신청은 멤버십 회원과 가입 3개월 체험자만 할 수 있다. 수업 시작 24시간 전까지 받는다(FR-093 · FR-108(대기 마감)).
3. 결제 취소가 1건 나면 대기 1번 한 명에게만 결제 기회를 알린다(FR-094).
4. 1번이 정해진 시간 안에 결제하지 않으면 다음 순번이 1번이 된다(FR-095(대기 무응답 승계)). 응답 시간 값은 **미정**이다.
5. 결제 기회는 수업 시작 3시간 전까지만 생기고, 그 뒤에는 대기 종료를 알린다 — 임시 확정(Q28).

대기 자리 알림은 광고성이 아닌 서비스 알림이다 — 임시 확정(Q27).

### 6-4. 멤버십

1. 회원은 가입일부터 3개월 동안 AI 검색·대기·학원 구독을 체험한다. 쿠폰은 체험에 없다(FR-112d(신규 가입 3개월 체험)).
2. 3개월 멤버십 3,000원 또는 연 멤버십 10,800원을 결제한다(FR-112(멤버십 결제수단)·FR-112a).
3. 3개월 멤버십은 결제할 때마다 1+1 쿠폰 1장을 바로 받는다. 연 멤버십은 1+1 대신 동반자 첫 수업 무료 쿠폰을 1년에 1장 받는다(FR-120 · FR-120b).
4. 언제든 해지할 수 있다. 다음 결제만 멈추고 낸 기간은 끝까지 쓴다(FR-297(멤버십 해지)).

|---|---|---|

| 환불 요청 | 결제 뒤 환불하지 않는다. 법이 요구할 때만 플랫폼이 환불 | FR-297a(멤버십 환불 없음) |
| 쿠폰을 한 번 씀 | 그 멤버십 결제는 청약철회 기간 안이라도 환불하지 않는다. 쓰기 전에 확인창으로 동의 — 출시 전 법률 검토 필수 | FR-297a |

### 6-5. 수업 등록 → 승인 → 공개

1. 강사가 학원 소속을 신청하고 대표가 승인한다. 대표가 보낸 초대 링크로 들어오면 바로 소속된다(FR-011).
2. 대표가 「수업 등록 권한」을 준 강사만 그 학원 이름으로 수업을 올린다(FR-050a(수업 등록 승인)).
3. 1단계(I2)에서 장르·구분·레벨·요일·시간·기간·홀·수강료를 넣는다.
4. 2단계에서 정규 수업은 대표 환불 공지가 읽기 전용으로 자동 입력되고(I2D), 이벤트형은 환불 마감일을 반드시 넣는다(I2E) — 2단계 구성은 추천안.
5. 강사가 `수업 등록` → `승인 중`. 대표에게 휴대폰 푸시가 가고, 누르면 승인 화면(O5)이 열린다.
6. 대표가 `승인` → `공개`. 회원 앱 검색·목록에 바로 나오고 신청·결제가 열린다.

**예외**

| 상황 | 처리 |
|---|---|
| 대표가 내용이 틀렸다고 봄 | `수정 요청`(사유 필수) → 강사 `임시 저장` 으로 되돌림 |
| 24시간 무응답 | 대표에게 같은 푸시를 한 번만 다시 보낸다 |
| 강사가 실수로 올림 | `승인 중` 동안 `등록 취소` → `임시 저장` |
| `공개` 뒤 금액·요일·시간·기간·정원 수정 | 다시 `승인 중`. 승인 전까지 옛 내용이 공개된 채로 남는다 |
| 대표 본인이 올린 수업 · 개인 레슨 | 승인 없이 바로 공개 |
| 같은 시간 강사 일정 · 같은 강의실 | 저장·게시 거부(FR-054 · FR-072) |

### 6-6. 정산 — 결제 → 보류 → 예정 → 완료 → 대표 승인 → 지급

1. **결제 확정** — 금액이 정산 `보류` 로 쌓인다(FR-289).
2. **보류** — 결제 완료부터 수업 시작 전까지(FR-128).
3. **정산 완료 예정** — 수업 시작 시각에 넘어간다. 금액은 보이지만 지급되지 않는다(FR-129(정산 시각 전이)).
4. **정산 완료** — 수업 기간 종료 시각에 넘어간다.
5. **학원 지급** — 정규·단기·개인 레슨은 매월 5일, PG 정산 분배로 학원 계좌에 들어간다. 이벤트형은 환불 마감일 다음 날 한꺼번에 지급한다(FR-282d · FR-282e).
6. **대표 승인** — 정산일에 앱이 강사별 지급액을 계산하고 대표가 확인·승인한다 — 임시 확정(Q14).
7. **강사 지급** — 베타: 대표가 지급 목록(이름·계좌·금액)을 내려받아 은행 대량이체 → 앱에서 「지급 완료」. 정식: 승인 버튼이 PG 지급대행을 호출 — 임시 확정(Q14).

| 상황 | 처리 | FR |
|---|---|---|

| 송금 반송 | 지급 보류로 돌리고 받는 사람에게 알림. 계좌 재등록·확인 뒤 다음 지급에 포함 — 추천안 | FR-133a(정산 지급 실패) |
| 분쟁·환불 요청 중·이상 거래·계좌 미확인·기관 요청 | 해당 금액 지급 보류, 사유·금액 통지 | FR-252(정산 보류) |

### 6-7. 휴강·행사 취소

**정규 수업 휴강·폐강**

1. 강사가 이번 회차만 휴강할지, 이후 회차 전체를 폐강할지 고른다. 최종 결정은 강사가 한다(FR-065(회차 휴강·폐강 선택)).
2. 결제한 모든 수강생에게 1분 안에 알린다(SC-014(변경 알림 1분)).
3. 회원은 7일 안에 「같은 과정의 다른 회차로 옮기기」 또는 「그 회차 금액 환불(결제액 ÷ 회차 수)」을 고른다. 고르지 않으면 환불한다. 보강 크레딧은 따로 만들지 않는다 — 임시 확정(Q16).
4. 학원·강사 사정의 휴강·폐강이면 예매 수수료도 돌려준다(FR-282a(예매 수수료 2,000원)).

**이벤트형 행사 전체 취소**(FR-099e(행사 일괄 취소))

1. 결정은 대표만 한다. 강사는 사유를 적어 요청할 수 있다.
2. 대표가 사유(불가항력 / 대표 개인 사정·학원 운영상 이유)를 고르고 확정한다.
3. 결제자 전원에게 알리고 PG 로 전액 일괄 환불한다. 예매 수수료도 돌려준다. 환불 마감일이 지났어도 같다.
4. 건마다 멱등키를 두고 실패 건은 재시도 목록에 남긴다.
5. 돌려받지 못한 PG·카드 수수료는 불가항력이어도 대표가 부담한다. 판매 수수료 5%는 받지 않고, 이미 지급한 돈은 다음 정산에서 상계한다.

### 6-8. 문의·분쟁

1. 회원이 묻는다. 시스템이 질문을 네 등급으로 나눈다 — T0 내 데이터(저장값을 그대로 읽음) · T1 정해진 지식(승인된 답) · T2 판단(AI 에이전트, 멤버십 혜택) · T3 사람(분쟁·개인정보·신고·확신 없는 질문). T0·T1 은 모델을 쓰지 않는다(FR-200(질문 4등급 분류)).
2. 결제·환불 분쟁·개인정보·신고·미성년자 문의는 모델에 보내지 않고 바로 사람에게 간다(FR-201(민감 문의 사람 배정)).
3. 사람 문의는 문의자가 검색해서 고른 학원의 대표에게 간다. 개인 레슨은 그 레슨의 소속 학원 대표에게 간다(FR-203(대표 선택 문의)).
4. 앱·웹 시스템 문의(계정·로그인·앱 오류·개인정보 삭제·신고·결제 시스템 장애)만 운영자가 받는다.
5. 대표는 1영업일 안에 답한다. 넘기면 대표에게 다시 알리고 회원에게 「답변 대기 중」을 보인다 — 임시 확정(Q21).

|---|---|---|
| AI 가 확신하지 못함 | 추측하지 않고 「확인해서 알려드리겠다」며 대표 선택 화면으로 넘긴다 | FR-202 · FR-203a |

| Q38(인원 차이 알림 기준과 수업 수정 제한) | 남녀 결제 인원 차이 3명 이상이면 전날 18:00 알림. 결제자가 있는 수업은 학원·장르·종목·구분을 못 고치고 금액·요일·시간·기간·정원은 대표 승인을 다시 받는다 | 기준 숫자, 판정 시각, 못 바꾸는 항목의 범위 |

| Q40(회차 하나의 시간·장소 변경 승인) | 한 회차만 바꾸면 대표 승인 없이 바로 반영하고 수강생·대표에게 알린다. 이후 회차 전부는 수업 수정으로 가서 대표가 다시 승인한다(보드 I34) | FR-050a(수업 등록 승인)의 재승인이 수업 전체 값에만 걸리는지 |
| Q41(강사 가입 규칙) | 아이디 영문 소문자·숫자 4~20자, 비밀번호 8자 이상 혼합, 필수 동의 3개·선택 1개, 아이디·비밀번호 찾기는 휴대폰 본인확인 하나(보드 I31·I31B) | 형식·동의 항목·찾기 수단 |
| Q42(입점 해지 때 남은 수업) | 결제된 수업은 끝까지 제공하고 정산도 정상(FR-256 문장 그대로, 보드 W26). 대체·환불 선택지는 두지 않았다 | 대체·환불 선택지를 줄지, 폐업 때 처리 |
| Q43(대표 앱의 끌 수 없는 알림과 환불 기한 미리 알림) | 환불·결제 실패·강사 지급 승인·카드 이의제기 알림은 끌 수 없다(보드 O34). 정규 환불 답할 기한 하루 전 오전 9시 미리 알림(보드 W27) | 끌 수 없는 묶음의 범위, 미리 알림 시각 |
| Q44(선택 업데이트 「나중에」 뒤 다시 알리는 간격) | `나중에` 뒤 7일에 한 번 더 알린다. 앱을 열 때 전체 화면으로 띄운다(보드 C32D) | 간격 7일, 전체 화면과 홈 위 창 중 어느 쪽 |
| Q45(권한 받은 강사가 관리 웹에서 보는 수업 범위와 포스터 읽기) | 자기가 그 학원 이름으로 올린 수업만 보고, 포스터 읽기는 대표와 같은 흐름으로 쓴다(보드 W30) | 범위를 자기 수업으로 한정할지, 학원 수업 전체를 볼지 |
| Q46(실시간 인기 수업 「전체 학원 순위」 토글을 켰을 때 가는 곳) | 정해진 곳이 없다. 토글 꺼짐 판만 그렸다(보드 C32A) | 켠 판 아래 「전체 학원 순위 ›」 링크의 도착 화면 |
| 필수 기능 점검 추천안 46개 | 모두 그대로 진행 | 항목별 확인(spec 「보완 2026-11-10」 표시) |
| 기타 미정 | 자동 추출 정확도 목표(전제 14), 사용량 한도 값(전제 17), 대상 레벨 복수 선택(FR-051), FR-062(빈 강의실 수업 제안) 본문 정의 | 각각 |

## 14. 용어

| 용어 | 뜻 |
|---|---|
| 정규 과정(정규 수업) | 기간 전체를 한 번에 신청·결제하는 반복 수업. 베이직·레이디 스타일도 정규로 본다. 환불은 학원 규정 |
| 이벤트형 | 이벤트·원데이·파티·공연·대회. 한 번 열리고 끝나는 상품. 계좌 결제만, 예매 수수료·공통 취소 규정·환불 마감일이 붙는다 |
| 개인 레슨 | 강사가 소속 학원에서 여는 1:1 10회 수강권. 결제·정산은 그 학원 |
| 환불 마감일 | 이벤트형 등록 때 반드시 넣는 날짜. 다음 날부터 취소·환불 불가 |
| 취소 잔여금 | 이벤트형 취소에서 환불하지 않고 남은 금액. 플랫폼과 대표가 5:5 로 나눈다 |
| 예매 수수료 | 이벤트형 1명당 2,000원. 플랫폼 몫, 원칙적으로 환불 안 함 |
| 판매 수수료 | 수업 결제의 5%. 입점 1년 면제 |
| 보류 | 결제 완료 ~ 수업 시작 전 정산 단계 |
| 정산 완료 예정 | 수업 시작 ~ 기간 종료 전 정산 단계. 금액은 보이지만 지급 안 함 |
| 정산 완료 | 수업 기간이 끝나 지급 대상이 된 단계 |
| 지급 보류 | 분쟁·차지백·계좌 미확인 등으로 지급을 멈춘 것. 정산 단계 「보류」와 다르다 |
| 상계 | 학원이 회사에 줄 돈을 정산금에서 빼는 것 |
| 대사 | 두 기록(PG 거래와 결제 원장, 콘솔과 원장)의 합계를 맞춰 보는 것 |
| 차지백 | 회원이 카드사에 결제를 문제 삼는 것(카드 이의제기) |
| 멤버십 | 회원용 유료 상품(3개월·연). AI 검색·대기·쿠폰·학원 구독 |
| 구독(학원 구독) | 학원 소식 받기. 유료 상품 이름이 아니다 |
| 수업 관리 플러스 | 강사용 유료 구독. 기본 기능은 무료 |
| 1+1 쿠폰 | 정가 정규 수업 1달 + 레벨 범위 안 다른 정규 수업 1달 무료 |
| 회원 | 수업을 듣는 사람(Dancer) |
| 강사 | 프리랜서 수업 진행자(Instructor). 여러 학원에 소속될 수 있다 |
| 대표 | 학원 운영자(Owner). 「업주」·「점주」는 쓰지 않는다 |
| 운영자 | 플랫폼의 앱·웹 시스템 관리자(Admin) |
| 결석 예정 | 회원이 수업마다 고르는 `참석 / 결석` 토글. 기본은 참석 |
