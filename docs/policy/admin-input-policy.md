# 학원 관리자 스케줄 등록 방식 정책

- 날짜: 2026-09-14

## 결정 사항

학원 관리자의 수업 스케줄(및 파티·공연·대회) 등록은 **포스터·전단지·스크린샷 업로드 → OCR 자동추출 → 관리자 검토 → 게시** 흐름으로 확정한다. `../guide/kdance-screens-spec.html`, `social-dance-academy-pitch.html`에 명세된 방식이며, 입점 영업 피치의 핵심 셀링 포인트("포스터 한 장만 올리면 자동 등록")이기도 하다.

`social-dance-app-dev-guide.html`에 있던 "관리자가 필드를 직접 입력하고 포스터는 화면 노출용일 뿐 데이터 추출에는 쓰지 않는다"는 서술은 이 결정과 상충되어 2026-09-14에 OCR 기반 흐름으로 수정했다.

## 적용 범위

- **수업 스케줄**: 포스터 업로드 → OCR 자동추출 → 검토 → 게시. 예약·결제 연동 필수.
- **파티 · 공연 · 대회**: 같은 업로드 폼 재사용, OCR 자동추출. 뉴스피드(전 학원 통합)에 노출.
- **학원별 공지**: OCR 대상 아님 — 관리자가 텍스트로 직접 작성(사진은 선택 첨부). 휴강·이벤트처럼 속도가 우선인 정보라 그대로 유지.

## 주의사항 (별도 확인 필요)

- 가격·정원처럼 되돌리기 어려운 필드는 OCR 오인식 가능성이 있으므로, 신뢰도가 낮은 항목을 "확인필요"로 표시하고 검토 단계를 건너뛰는 경로는 만들지 않는다 (`social-dance-app-dev-guide.html` 원칙 유지).
- OCR 파이프라인의 구체적 구현 방식(모델 선택, 자체 구축 vs 외부 API, 정확도 목표치)은 아직 미정 — 구현 단계에서 별도 결정 필요.
- MVP 6개 화면 범위(업로드→검토→게시→예약→결제→정산)에 OCR 파이프라인이 포함되므로, 로드맵상 OCR 개발이 초기 단계로 앞당겨진다 — 기존 로드맵의 "먼저 검증 후 확장" 순서에 미치는 영향은 재검토 필요.
