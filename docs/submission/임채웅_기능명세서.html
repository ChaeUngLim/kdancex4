1. 기능 개요

K-DanceX4 는 소셜 댄스 학원 수업을 찾고, 결제하고, 수강 이력과 레벨을 쌓는 Android 앱과 관리자 웹이다. 회원은 취향·일정·레벨에 맞는 수업을 고르고, 강사는 수업과 수강생을 관리하며, 대표는 학원·강사·수업 승인을 한곳에서 처리한다. AI 는 수업 검색(AI 플래너), 포스터 읽기, 홍보 이미지·소개 문구 초안을 맡는다.

1-3. 핵심 기능 지도

2. 목적

이 서비스는 양면 시장(two-sided market)이다. 수업을 찾는 회원과 수업을 여는 강사·대표 가운데 한쪽만 있으면 거래가 한 건도 생기지 않는다. 그래서 「회원이 수업을 찾아 결제한다」(US1)와 「강사가 수업을 열고 자리를 관리한다」(US2)를 둘 다 최우선(P1)에 두었다.

2-1. 풀려는 문제

누구지금의 불편제품의 답
대표블로그·SNS 로는 취향이 맞는 수강생을 걸러 찾기 어렵다. 예약 확인·알림·결제 정리를 손으로 한다. 수업 등록이 번거롭다장르·지역·시간 검색, 결제 즉시 캘린더 등록과 알림, 포스터 한 장으로 수업 초안 만들기(FR-073(포스터 자동 추출)) + 검토 필수(FR-074(추출 검토 필수))
강사여러 학원을 다녀 일정이 흩어지고, 수강생 레벨·이력이 쌓이지 않는다학원이 달라도 겹치는 수업 저장 거부(FR-054(강사 일정 충돌 거부)), 세부 장르별 레벨과 개강 후보(FR-164(개강 후보 추천))
회원여러 학원 수업을 한곳에서 보기 어렵고, 남·여 짝 수업이라 정원이 성별로 갈리며, 학원마다 환불 규정이 다르다한 화면 검색, 「남 ○석·여 ○석」 표시(FR-092(성별 정원)), 결제 전 학원 환불 공지 표시(FR-282(결제 화면 필수 표시))

5. 오류처리

5-1. 공통 오류 응답 모양

모든 /api/** 오류는 사람이 읽는 한국어 문장(detail)과 기계가 읽는 코드(code)를 함께 준다. 검증 실패에만 칸별 fields 가 붙는다. 본문에 스택·SQL·연락처·환불 계좌를 담지 않는다(FR-299(결제 정보 보안)). /api/auth/** 는 Better Auth 모양을 그대로 쓰되 429 만 우리 모양으로 낸다.

{ "detail": "사람이 읽는 한국어 문장", "code": "SEAT_SOLD_OUT" }

{ "detail": "입력값을 확인해 주세요", "code": "VALIDATION_FAILED",
  "fields": [ { "path": "baseSubGenre", "message": "…" } ] }

HTTP 429 · Retry-After: 840
{ "detail": "잠시 뒤 다시 시도해 주세요", "code": "RATE_LIMITED", "retryAfterSeconds": 840 }

5-3. 멱등키(Idempotency-Key)와 중복 처리

대상키다시 오면
POST /api/orders헤더 Idempotency-Key(필수, 8~200자) + 회원200 + 처음 주문 그대로. DB 유니크 제약이 최종 판정
POST /api/orders/{id}/cancel주문 상태이미 취소면 200 같은 본문, 다른 상태면 409
POST /api/payments/webhook헤더 webhook-id200, 아무것도 바꾸지 않음
결제 확정주문 상태 조건부 갱신 pending→paid0행이면 이미 처리된 것
POST /api/ai/promo-images · 포스터 읽기헤더 Idempotency-Key(필수)같은 생성·같은 작업을 돌려주고 횟수를 다시 빼지 않는다

삽입 경합은 INSERT … ON CONFLICT DO NOTHING RETURNING id 로 받고, 돌아온 행이 없으면 이긴 행을 다시 읽어 같은 결과로 맞춘다. 자리·횟수 차감은 「남아 있을 때만 줄이는」 조건부 UPDATE 한 문장이라 동시 요청에도 정원과 한도를 넘지 않는다.

요구구현

앱 세션 제한(ADR-007)앱은 2단계를 묻지 않는 대신 아이디·IP 15분 5회 실패 제한을 걸고, 앱 세션은 웹 콘솔·계정 관리 경로를 못 쓴다. 비밀번호만 알면 대표 앱에서 회원 정보를 볼 수 있다는 위험은 사용자가 알고 골랐고, 개인정보 안전성 확보조치 기준 해당 여부는 공개 운영 전 확인이 남았다
로그인·요청 제한로그인·인증 코드 15분 5회, 본인확인 하루 5회, 결제 시작 분당 10회. Redis 에 세고 Redis 가 꺼지면 막는다. Redis 키에 IP·계정 원문을 남기지 않는다
비밀번호Better Auth 해시. 없는 아이디도 해시 지연을 같게 두어 계정 유무를 흘리지 않는다
개인정보 최소 노출회원은 닉네임으로만 보인다. 연락처는 기본 가림, 전체 열람은 사유·열람자 기록(SC-025). 강사 화면은 나이 대신 연령대. 위치는 저장하지 않는다(FR-186)
결제 정보카드번호를 저장하지 않고 PG 식별값만. 환불·정산 계좌는 암호화·가림 표시
감사 기록결제·환불·개인정보·권한 조작은 수행자·시각·대상·전후 값(FR-185)
AI에이전트는 DB 에 직접 접속하지 않고 읽기 전용 도구만 쓴다. 질문 기록은 전화·메일·계좌 모양을 가린다. 사용자 입력은 데이터 칸으로만 넣어 프롬프트 주입을 막는다(test_prompt_injection_guard.py). AI 생성물에 생성 표시
